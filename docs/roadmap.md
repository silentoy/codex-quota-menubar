# Codex Quota Menubar 后续迭代路线图

本文档用于记录 v1.6+ 的后续迭代方向，帮助后续开发按版本拆任务、验收和发布。当前路线图只描述计划，不代表已完成能力。

## 当前基线

- 当前发布版本：v1.5.0。
- 已具备能力：菜单栏圆环/百分比展示、主面板额度详情、24 小时/7 天/30 天趋势图、5 小时额度与周额度瓶颈判断、低额度提醒、Telegram 推送、Bark 推送、LaunchAgent 开机自启、中英文切换。
- 当前数据源：固定通过 `~/.codex/auth.json` 中的 Codex 登录态请求 ChatGPT usage 接口。
- 当前验证基线：`swift test` 已通过 41 个测试。
- 当前优先级：先提升稳定性、可诊断性和发布确定性，再考虑新增功能。

## v1.6：数据源稳定性与刷新诊断

### 目标

让用户在额度读取失败时知道“为什么失败、是否还能显示上次结果、下一步该怎么处理”，减少接口变化或登录态失效带来的黑盒感。

### 核心改动

- 增强 Codex usage 接口失败分类，至少区分网络失败、HTTP 401/403、HTTP 5xx、token 缺失、token 刷新失败、账号 ID 缺失、接口结构变化。
- 在主面板或设置页增加诊断摘要，展示最近一次成功刷新时间、最近一次失败原因、连续失败次数、当前是否使用上次成功结果。
- 增加“一键复制诊断信息”能力，便于排查问题；导出内容必须脱敏，不包含 access token、refresh token、Bot Token、Bark Device Key 等敏感凭证。
- 统一自动刷新、手动刷新、睡眠唤醒刷新后的状态文案，避免同一类失败在不同入口展示不同含义。
- 保留现有 3 秒手动刷新防抖，避免用户连续点击触发重复请求。

### 验收标准

- 无 `auth.json`、token 过期、token 刷新失败、usage 接口 401/403/5xx、接口结构缺字段时，界面能展示可理解的失败原因。
- 当非强制自动刷新失败且已有上次成功数据时，仍能明确提示“显示上次结果”。
- 诊断复制内容不包含任何 token、Device Key 等敏感原文凭证；如需包含 Chat ID，应明确脱敏。
- `swift test` 通过，并补充覆盖失败分类和连续失败恢复的测试。

## v1.7：设置页收敛与通知可靠性

### 目标

让设置页更像一个稳定的 macOS 工具设置中心，减少历史遗留选项和隐藏状态造成的理解成本，同时提升推送配置排错能力。

### 核心改动

- 设置页按“通用、数据源诊断、提醒、推送、启动”重新组织，保持同类控件的样式和交互一致。
- 当前版本已固定使用 Codex 登录态，后续应清理或隐藏仍停留在代码里的本机状态/手动填写入口和无效设置，避免后续维护误判。
- Telegram 和 Bark 区块增加最近一次测试结果、最近一次自动通知结果和失败原因。
- 推送测试按钮在发送中保持禁用，失败时展示明确原因，例如缺配置、URL 非法、HTTP 错误或服务端错误。
- 继续使用 macOS Keychain 保存推送凭证，不把凭证写入 UserDefaults、日志或诊断导出。

### 验收标准

- 设置页无需滚动或只需少量滚动即可完成常用配置，分组标题和控件含义清楚。
- Telegram/Bark 缺配置、配置错误、服务端返回错误、发送成功四类状态都有可见反馈。
- 清理遗留数据源入口后，README 中“固定 Codex 登录态数据源”的描述与代码行为一致。
- `swift test` 通过，并补充通知状态、脱敏诊断和设置状态迁移相关测试。

## v1.8：发布脚本与打包自检

### 目标

降低发版时的手工操作风险，让每次发布都能稳定完成构建、测试、打包和产物检查。

### 核心改动

- 扩展 `scripts/check.sh`，覆盖构建、测试、必要的文档/版本一致性检查。
- 增强 `scripts/build-app.sh` 打包自检，确认 `.app` 中可执行文件存在、版本号正确、图标资源存在、产物 zip 生成成功。
- 新增 release checklist，明确发版前需要检查的项目：版本号、CHANGELOG、README 重点、测试结果、打包产物、首次运行提示。
- 为 release notes 保持固定模板，减少每次手写遗漏。

### 验收标准

- 执行一条检查命令即可确认源码构建、测试和基础打包前置条件。
- 打包脚本失败时能给出具体失败步骤，而不是只显示通用 shell 错误。
- release checklist 能被独立照着执行，新维护者也能完成一次发版。
- 发版产物能启动，菜单栏图标出现，设置页能打开，开机启动提示符合 `.app` 运行条件。

## 风险与原则

- ChatGPT usage 接口是 ChatGPT 网页端后端接口，不是公开稳定的 OpenAI Platform API，可能随官方页面或后端调整而失效。
- 后续迭代优先增强失败诊断、降级展示和用户可操作提示，不承诺长期兼容非公开接口。
- 不在本地保存 prompt、token 明文、完整请求响应或额外账号数据；历史记录继续只保存额度百分比、刷新次数和聚合消耗数据。
- 功能实现保持轻量，避免为了低复用逻辑过度抽象；同一项目中的相同控件样式和交互保持一致。
